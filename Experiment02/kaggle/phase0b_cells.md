## Cell 3 — pinned install (GPU path, with CPU fallback)

This repo's own `requirements.txt` pins `dgl==2.3.0+cu118` next to a plain `torch==2.2.1`
that PyPI would otherwise resolve to a cu121 build — see ARCHITECTURE.md's note on this if
you want the detail. To avoid that mismatch we pin both explicitly to cu118 from their
respective wheel indices, matching what the repo's own pin implies was actually used.

```python
import subprocess, sys

def sh(cmd):
    print("+", cmd)
    return subprocess.call(cmd, shell=True)

GPU_OK = sh("nvidia-smi") == 0

if GPU_OK:
    rc = sh(f"{sys.executable} -m pip install -q torch==2.2.1 --index-url https://download.pytorch.org/whl/cu118")
    rc |= sh(f"{sys.executable} -m pip install -q dgl==2.3.0+cu118 -f https://data.dgl.ai/wheels/cu118/repo.html")
    if rc != 0:
        print("GPU install failed, falling back to CPU wheels")
        GPU_OK = False

if not GPU_OK:
    sh(f"{sys.executable} -m pip install -q torch==2.2.1")
    sh(f"{sys.executable} -m pip install -q dgl==2.3.0 -f https://data.dgl.ai/wheels/repo.html")

# the rest of the pinned deps main.py actually imports (see requirements.txt for the full
# frozen list; this is the minimal set that src/*.py imports)
sh(f"{sys.executable} -m pip install -q numpy==1.26.4 pandas==2.2.2 scipy==1.14.0 "
   f"sympy==1.13.1 scikit-learn==1.5.1 tqdm==4.66.4 line_profiler==4.1.3 openpyxl==3.1.5 gdown")
```

states the raw graphs come from GADBench and that edge labels were generated by the authors
via `P_anom(i,j) = avg(P_i_anom, P_j_anom)` — see `src/data_prep/build_els_datasets.py` for
the full citation and reasoning. GADBench publishes its raw graphs as a single Google Drive
zip linked from its own README.
